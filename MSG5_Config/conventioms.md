# Конвенции работы с параметрами (MSG5_Config)

## 1. Поток данных
1. Источники (CLI > FILE > ENV > STDIN) читают значения.
2. `Resolver` сливает их по приоритетам → `ResolvedOptions`.
3. `apply_defaults()` добавляет недостающие (если описаны в `CommandSpec`).
4. `validate_against_spec()` проверяет обязательность, типы, enum.
5. Итог: готовый контейнер опций для приложения.

## 2. Имена и поиск
- У каждой опции есть **каноническое имя** (`db.host`).
- **CLI**: только `--db.host` (длинный ключ, ровно по канону).
- **ENV**: `MSG5_` + snake-uppercase (`db.host` → `MSG5_DB_HOST`).
- **FILE / STDIN (JSON)**: только канонические ключи.
- Никаких алиасов, коротких имён, магии.

## 3. Неизвестные и недостающие
- **Unknown key**: не падаем, а выдаём `user-warning`, ключ игнорируется.
- **Missing key**:
  - если в `spec.default_value` → берём дефолт;
  - если `required` без дефолта → `user-error`, процесс завершается;
  - если `optional` → пропускаем.

## 4. Ошибки и валидация
- **Wrong type / invalid enum** → `user-error`, процесс завершается.
- **Системные ошибки источников** (файл не прочитан, ENV недоступен) → `system-error`.
- Все ошибки и варнинги — человекочитаемые, с указанием ключа и источника.

## 5. Принцип приоритета
- Ранний источник в списке → выше приоритет (не переписывается позже).
- `ResolvedOptions::push()` по умолчанию `override=false`.
- Если «очень нужно» — можно вызвать с `override=true`.
