# Конвенции параметров — кратко (дополнения)

> Быстрая памятка по именованию ключей, нормализации и классам ошибок. Синхронизировано с текущей реализацией `MSG5_Config`.

## 0) Поток (актуально)
1) Источники читают значения (порядок задаёт вызывающий код; *рекомендовано*: `CLI > FILE > ENV > STDIN`).  
2) `Resolver` сливает по правилу **«ранний сильнее»** (первое значение фиксируется, поздние не перезаписывают).  
3) *(План P4)* `apply_defaults()` — заполняет пропуски.  
4) *(План P4)* `validate_against_spec()` — required/type/enum.

## 1) Канонические имена
- **Канон в `CommandSpec`**: ключи описываются в `lower.dotted.case` (напр. `db.host`, `log.level`).
- Источники возвращают пары **только по ключам из `CommandSpec`** (см. ниже по каждому типу).

## 2) Нормализация (сейчас vs план)
- **FILE / STDIN (сейчас)**: ищем ровно по `json_path`, иначе по `key` как есть (без авто-нормализации).  
  *(План P5)*: добавить опциональную нормализацию входных ключей до `lower.dotted.case` и предупреждения о «лишних» ключах.
- **CLI (сейчас)**: используются только заявленные `cli_flags` для каждой опции; неизвестные флаги игнорируются и логируются (`CLI_FLAG_UNKNOWN`).
- **ENV (сейчас)**: ищем по `opt.env_names`, иначе `PREFIX + TO_ENV_KEY(opt.key)`, где `TO_ENV_KEY` = `UPPER_SNAKE` от канона (`db.host` → `DB_HOST`). Префикс задаёт приложение (например, `MSG5_`).

## 3) Классификация ошибок/диагностики
- **system-error**: I/O, парсинг, отсутствие файла, ошибки чтения stdin и т.п.  
  Примеры событий: `FILE_NOT_FOUND`, `FILE_EMPTY`, `FILE_PARSE_ERROR`, `STDIN_PARSE_ERROR` (обычно `Warn`/`Error`).
- **user-warning**: неизвестные CLI-флаги, (опционально) лишние ключи во входных данных.  
  Пример: `CLI_FLAG_UNKNOWN` (`Info`/`Warn`).
- **Информационные события**: `*_READ_OK`, `ENV_FOUND_*`, `STDIN_EMPTY` и т.п. (`Info`).
- **Секреты**: если у опции установлен флаг `OptSecret`, в логах значение маскируется (`****`), а в итоговом конфиге хранится фактически.

## 4) Примеры
- **CLI**: `--db.host=localhost` → ключ `db.host`, origin=CLI.  
  `--unknown=42` → не попадает в результат, `CLI_FLAG_UNKNOWN` в логах.
- **FILE/STDIN** (плоский JSON): `{ "db.host": "localhost", "log.level": "debug" }`  
  → ключи из `CommandSpec` попадут как есть; лишние поля игнорируются без предупреждений *(пока)*.
- **ENV**: `MSG5_DB_HOST=localhost` → ключ `db.host`, origin=ENV.  
  `DB_HOST` без префикса — **не** находится (если нет в `env_names`).

## 5) Итоговая печать (план)
- `dump_effective()` выводит пары `key=value` с источником (`Cli/File/Env/Stdin/Default`), секреты маскируются.

## 6) Чек-лист соответствия (быстрый)
- [ ] Порядок источников задан вызывающим кодом; «ранний сильнее» соблюдается.  
- [ ] Источники возвращают только ключи из `CommandSpec`.  
- [ ] FILE/STDIN: плоский JSON, без автопоиска и без нормализации (пока).  
- [ ] ENV: префикс приложения применён, `env_names` приоритетнее.  
- [ ] CLI: фильтрация по `cli_flags`, неизвестные логируются.  
- [ ] Секреты маскируются в логах, фактические значения сохраняются в результирующей конфигурации.
