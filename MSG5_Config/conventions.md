# Конвенции для MSG5_Config

> Краткие правила для источников конфигурации и резолвера. Это **норматив** для реализации и тестов.

## 0) Общие принципы
- **Никаких исключений наружу.** Источники никогда не бросают; все проблемы фиксируются событиями через `emit(level, code, details)` и работа продолжается.
- **Слои только те, что переданы.** Никакого автопоиска файлов/профилей/пути по умолчанию внутри источников.
- **Приоритет:** *«ранний сильнее»*. Ключ, уже установленный ранним источником, поздними не перезаписывается.
- **Секреты маскируем** в логах (см. §5). В результат (`ResolvedOptions.values`) кладём фактическое значение.
- **Возвращаем только ключи из спецификации (`CommandSpec`).** Источники не «обогащают» конфиг произвольными полями.

## 1) Порядок слоёв
- Порядок задаётся вызывающим кодом (вектор источников).
- **Рекомендуемый дефолт:** `CLI > FILE > ENV > STDIN`.
- Допускается иной порядок под конкретное приложение/команду.
- **Внешним проектам рекомендуется создавать источники через фабрики** из `msg5/config/Sources.h`.

## 2) Нормализация ключей
- Каноническая форма ключа в `CommandSpec`: `lower.dotted.case` (пример: `db.host`, `server.listen.port`).
- Источники **сопоставляют** вход с каноникой из `CommandSpec`:
  - FILE/STDIN: ищут по `json_path` (если задан) иначе по `key` **как есть**.
  - CLI: флаги перечисляются явно в `cli_flags`.
  - ENV: имя строится как `PREFIX + TO_ENV_KEY(key)` (см. §4), если не задан `env_names`.
- Если требуется поддержка дот-путей для вложенного JSON, это будет включено отдельно (P8). Пока — плоский JSON.

## 3) FILE (базовый файловый источник)
- Конструктор принимает **ровно один путь**. Источник **не** подбирает файлы, не ищет профили.
- Читает файл как **плоский JSON-объект** (`{"k":"v", "n":123, "b":true}`) и формирует пары **только для ключей из `CommandSpec`**:
  - Если у опции задан `json_path` — используем его; иначе — `key`.
  - Нескалярные значения считаются неподдерживаемыми.
- Диагностика: `FILE_NOT_FOUND`, `FILE_EMPTY`, `FILE_READ_ERROR`, `FILE_PARSE_ERROR`, `FILE_READ_OK` (Info).

## 4) ENV (переменные окружения)
- Префикс задаёт приложение (пример: `MSG5_`) и передаётся в конструктор источника.
- Порядок поиска значения для опции:
  1. Перебираем `opt.env_names` (если список непустой). Как только нашли существующую — берём её.
  2. Иначе строим имя `PREFIX + TO_ENV_KEY(opt.key)` и ищем его.
- `TO_ENV_KEY(x)`: перевести в UPPER_CASE, заменить `.` на `_`, убрать недопустимые символы.
- Пустая строка — допустимое значение (отличать «не существует» от «пустое»).

## 5) CLI (аргументы командной строки)
- Разрешены **только** флаги, перечисленные в `opt.cli_flags` для каждой опции.
- В `prepare(spec)` источник строит кэш соответствий `flag → key`.
- Неизвестные флаги **игнорируются** и логируются как `CLI_FLAG_UNKNOWN` (Info/Warn — на усмотрение приложения).

## 6) STDIN (prompt)
- Читает весь ввод до EOF. Ожидается **плоский JSON-объект**.
- Возвращает пары **только** для ключей, присутствующих в `CommandSpec` (по `json_path` или `key`).
- Диагностика: `STDIN_EMPTY` (Info), `STDIN_PARSE_ERROR` (Warn), `STDIN_READ_OK` (Info).

## 7) Логирование и уровни
- Источники используют уровни `Info / Warn / Error`.
- Рекомендуемое отображение для UX:
  - **system-error**: ошибки ввода-вывода, парсинга (`FILE_PARSE_ERROR` и т.п.) → `Error`.
  - **user-warning**: неизвестные флаги CLI, лишние поля (если проверяются) → `Warn`.
  - Информационные события успешной работы → `Info`.
- События всегда содержат идентификатор источника: `cli`, `file:<path>`, `env:<prefix>`, `stdin`.

## 8) Секреты
- Опции отмечаются битом `OptSecret` в `OptionSpec.flags`.
- В логах значение таких опций **маскируется** (например, `****`).
- В результирующем конфиге значение хранится как есть (для дальнейшего использования).

## 9) Валидация и дефолты (позже)
- После слияния слоёв:
  - `apply_defaults()` — подставляет `default_value`, помечая `Origin::Default`.
  - `validate()` — проверяет `required`, `type`, `enum`.
- Ошибки валидации — класс **user-error** (не путать с system-error).

## 10) Произвольные расширения
- Разрешены **только** через явную спецификацию (`CommandSpec`):
  - CLI-алиасы — в `cli_flags`;
  - альтернативы для ENV — в `env_names`;
  - структура JSON — через `json_path`.
- «Магия» (автодогадки, поиск профилей, совпадения по префиксу и т.п.) запрещена в базовых провайдерах.

## Чек-лист для ревью источника
- [ ] Не бросает исключений наружу; все ошибки → `emit`.
- [ ] Возвращает только ключи из `CommandSpec`.
- [ ] Соблюдает приоритет «ранний сильнее» на уровне резолвера (источник этому не противоречит).
- [ ] FILE — один путь, без автопоиска; плоский JSON.
- [ ] ENV — соблюдён префикс, корректно различает «нет переменной» vs «пустая строка».
- [ ] CLI — фильтрация по `cli_flags`, неизвестные флаги логируются.
- [ ] STDIN — плоский JSON, фильтрация по `CommandSpec`.
- [ ] Маскирование секретов в логах по `OptSecret`.
- [ ] События содержат корректный `source_id`.
